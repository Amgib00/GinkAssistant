Get startedQuickstart

One call, a whole agent

No servers, queues or agent loop to build. Give the agent a task and an environment; it does the steps and returns what it did, the files it changed and its answer.

Workspaces that remember

Each environment keeps its files between calls. Upload data once, continue a task later with previous_interaction_id, and open the same files in Gink Genie.

Gink Genie’s agent inside

The same file tools Gink Genie uses — find, search, read, edit, write — plus web search with sources. Every call saves a version first, so changes can be undone.

Quickstart

Create an API key in the console, then make your first request.

1. Create an API key (or pip install gink-ai and gink login).

2. Send a task with environment: "remote" for a new workspace.

3. Read output_text, and the files under environment.

Long tasks: add "background": true and check GET /v1/interactions/{id}.

# pip install gink-ai      (then: gink login, or set GINK_API_KEY)
from gink import Client

client = Client()
interaction = client.interactions.create(
    agent="gink-agent",
    input="Plot solar energy growth in Senegal since 2015 and write slides in HTML",
    environment="remote",
)
print(interaction.output_text)
print("Files:", interaction.files_changed, "in", interaction.environment)

# live, step by step
for event in client.interactions.create(input="Add this year's numbers",
                                        previous_interaction_id=interaction.id, stream=True):
    print(event.type, event.data)
const GINK = "https://gink-server.onrender.com/v1";
const res = await fetch(`${GINK}/interactions`, {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.GINK_API_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({
    agent: "gink-agent",
    input: "Plot solar energy growth in Senegal since 2015 and write slides in HTML",
    environment: "remote",
  }),
});
const interaction = await res.json();
console.log(interaction.output_text, interaction.files_changed);

Reference

Every request uses your API key: Authorization: Bearer gink_….

RequestWhat it does
POST /v1/interactions{"agent": "gink-agent", "input", "environment": "remote" | id, "previous_interaction_id", "background", "max_steps" (1–30, default 15), "tools": ["files", "web_search"]} → an interaction: id, status (running, completed, incomplete, failed, cancelled), output_text, steps, files_changed, environment.
"stream": trueLive: the response is a stream of server-sent events — step (each step the moment it’s done), status, then done with the whole interaction. Try curl -N.
GET /v1/interactions/{id}The interaction now (for background ones).
POST /v1/interactions/{id}/cancelStops before its next step.
POST /v1/environments{"name"} → a new, empty environment.
GET /v1/environments, GET /v1/environments/{id}Your environments and their files.
PUT /v1/environments/{id}/files/{path}Upload a file (the request body is its content).
GET /v1/environments/{id}/files/{path}Download a file.
DELETE /v1/environments/{id}Delete an environment and its files.

Live information: the agent always knows today’s date and time, gets live data (weather, exchange rates, prices…) when your input asks for it, and searches the web for the rest, with sources. Gink Genie uses the same live web search.

In the terminal: gink agent "task" (steps appear live), and gink env list | new | files | pull | push | rm for the workspaces. Each workspace is also a Gink Genie project: what the agent did shows up in its conversation there.

Good to know: an interaction counts as one message toward your daily allowance. Environments are Gink Genie projects (same limits). The agent doesn’t run code on the server — it writes the code and tells you how to run it. Age, parental-control and workspace rules apply, as everywhere in Gink.
